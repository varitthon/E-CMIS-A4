Source map

The repo carries three competing token sets. This system is built on the one the 22 workflow pages actually load; the other two are documented so nobody re-adopts them by accident.

ecmis-modal.css 24 pages Canonical, scoped. SweetAlert2 content only; every rule is deliberately nested under .swal2-container to win on specificity. Do not un-scope it.

Status

Each status carries three roles: a bg (tint behind a badge), a text (label on that tint), and a fill (solid, for dots, borders and solid badges). They are not interchangeable — the fill is too light to read as text, the text too dark to read as a fill.

Read-only display

The single most repeated pattern in the app: information the user must read but cannot change. It is visually distinct from a disabled input — a sunken panel, not a dead form field — so users stop trying to type into it. Widths come from .form-grid-2 / .form-grid-3, already canonical in ecmis-shell.css; a full-width field adds .span-2 / .span-3.

Adoption

assets/ecmis-design-system.css is additive — right now only this page loads it, so no existing screen has changed. Migrate one page at a time, lowest-risk first.

StepDo this
1 Add <link rel="stylesheet" href="assets/ecmis-design-system.css"> after ecmis-shell.css, before the page's own <style>. Nothing renders differently yet — the ds- prefix collides with nothing.
2 Swap the inline-styled badges for classes: style="background:#dcfce7;color:#166534" → class="ds-badge ds-badge-success". Highest value, lowest risk — start here.
3 Rename the page's markup to the ds- classes (.form-card → .ds-card, .step-item.completed → .ds-step.is-complete), then delete those rules from the page's <style> block.
4 What should remain in a page's <style>: only genuinely page-specific layout. If a rule appears on two pages, it belongs in the system.
5 Leave ecmis-modal.css exactly as it is — its .swal2-container scoping is load-order defense, not redundancy.

Open this page beside any workflow screen to check a value, or run document.body.classList.add('dark-mode') in the console to verify a component in dark mode — the token layer flips with the shell.
